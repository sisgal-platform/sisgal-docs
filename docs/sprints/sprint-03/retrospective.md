## Objetivo

Analizar la forma de trabajo del equipo durante el Sprint 03, identificar aspectos positivos, oportunidades de mejora y acciones que puedan aplicarse en los siguientes Sprints.

## ¿Qué funcionó bien?

Durante el Sprint se identificaron los siguientes aspectos positivos:

- Las historias de usuario tenían un alcance claro antes de iniciar el desarrollo.
- La asignación de responsabilidades permitió que cada integrante se concentrara en sus historias.
- Las Daily permitieron realizar seguimiento al avance y detectar oportunamente posibles dificultades.
- Las funcionalidades desarrolladas tuvieron continuidad con los módulos implementados durante los Sprints anteriores.
- El equipo logró completar las seis historias comprometidas dentro del periodo establecido.
- La coordinación entre frontend y backend permitió avanzar en las funcionalidades sin bloqueos críticos.

## ¿Qué se puede mejorar?

Se identificaron las siguientes oportunidades de mejora:

- Mejorar la estimación del esfuerzo requerido para las tareas técnicas.
- Identificar con mayor anticipación las dependencias entre historias.
- Mantener una actualización más frecuente de los estados de las tareas en Azure DevOps.
- Reservar tiempo suficiente para validaciones antes del cierre del Sprint.
- Continuar mejorando la definición de criterios de aceptación para reducir ajustes durante el desarrollo.

## Conclusión

El Sprint 03 permitió consolidar el trabajo colaborativo del equipo y completar las historias de usuario comprometidas.

El principal aprendizaje fue la importancia de mantener una definición clara de las historias, identificar las dependencias antes de iniciar el desarrollo y realizar seguimiento continuo durante el Sprint.

Las acciones de mejora identificadas serán consideradas durante la planificación y ejecución del Sprint 04.
