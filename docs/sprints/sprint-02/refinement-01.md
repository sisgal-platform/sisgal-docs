## Dudas y aspectos discutidos

Durante la sesión se revisó el alcance de las historias y se aclararon dudas relacionadas con el comportamiento esperado de las funcionalidades.

Los principales temas tratados fueron:

- Información requerida para el registro de empleados.
- Información que debe estar disponible para las consultas.
- Alcance del detalle de un empleado.
- Información y estructura necesaria para el modelo de base de datos.
- Comportamiento esperado para la parametrización de sucursales.
- Comportamiento esperado para la parametrización de cargos.
- Relación de estas parametrizaciones con las funcionalidades de empleados.

## Ajuste de criterios de aceptación

Después de resolver las dudas identificadas, se revisaron los criterios de aceptación de las historias.

Los ajustes estuvieron orientados a:

- Especificar con mayor claridad las condiciones de cada funcionalidad.
- Definir de forma más precisa los datos que deben visualizarse o registrarse.
- Reducir ambigüedades en la interpretación de las historias.
- Establecer condiciones verificables para determinar cuándo una historia cumple con el alcance esperado.
- Alinear los criterios con el comportamiento esperado por el equipo.

## Resultado

Las historias fueron refinadas y sus criterios de aceptación fueron ajustados para proporcionar una definición más clara del comportamiento esperado.

Las dudas identificadas durante la sesión fueron discutidas por el equipo antes de iniciar la planificación del Sprint.

## Acuerdos

- Utilizar los criterios actualizados como referencia durante el desarrollo.
- Mantener las historias de usuario enfocadas en el comportamiento funcional esperado.
- Revisar nuevamente cualquier criterio que genere dudas durante la implementación.
